# HowFar

**Ever searched for the nearest available bikeshare station? Wondered what events
are happening today? Or where the closest park to relax in is? If so, this app is
just the thing for you.**

HowFar shows you the nearest events and facilities Toronto has to offer. Updates
come straight from the city's municipal APIs wherever possible, so you always
have the best information available — and it's completely free. Since this app
costs me nothing to host, it stays free for you too: free as in free coffee, and
free as in free speech, under the GPL-3.0 license.

## Cards

| Group      | Cards                                              |
| ---------- | -------------------------------------------------- |
| Bikes      | Bike Share bikes available, return docks available |
| TTC        | Metro station, streetcar (N/S), streetcar (E/W)    |
| Facilities | Public library, park, drop-in skate                |
| Other      | NP Square events, concerts, sports, Tim Hortons    |

The four event cards (NP Square, concerts, sports, skating) show a **+** beside
the title when two or more options are on today, expanding to list the rest.

Preferences live in `localStorage` and are set from the ⋮ menu: bike type
(regular / electric / both), hide TTC, show 19+ drop-in skates, and hide sports.

## How it works

There is no backend. The site is static files on GitHub Pages, and all
location logic runs in the browser so "nearest" and "today" are always
evaluated against the user's actual position and clock. A daily GitHub Action
fetches event data from city APIs and Ticketmaster, bakes it into a JSON file
and deploys the site — so the data stays fresh without any server to maintain.

Data arrives via two pre-generated JSON files, on very different cadences:

```
generate_data.py  --(manual, occasional)-->  toronto_data.json    (committed)
fetch_events.js   --(GitHub Actions, daily)-->  toronto_events.json  (gitignored)
                                                      |
                                    index.html + app.js reads both
```

### toronto_data.json — static POIs

Committed to the repo, regenerated by hand when it goes stale. Currently
13 metro stations, 749 streetcar stops, 40 libraries, 1,643 parks, 310 Tim Hortons.

```sh
pip install requests
python3 generate_data.py
```

Sources: TTC GTFS feed (streetcars and stations), Toronto Open Data green-spaces
GeoJSON (parks), and Overpass API over a 5×5 grid of the city (libraries, Tim
Hortons, TTC stations). Overpass is queried by grid because a single city-wide
query times out; failed cells are retried once, and the script **aborts without
writing** if any cell still fails, so a partial result can never overwrite good data.

This is deliberately not in CI — it is slow, hits Overpass hard, and the
underlying data changes on the order of months.

### toronto_events.json — daily events

Built by `fetch_events.js` in GitHub Actions (6am UTC / 2am Toronto), plus on
every push to `master`. Not committed; it only exists in the deployed artifact.

| Source                            | Provides                      | Notes                         |
| --------------------------------- | ----------------------------- | ----------------------------- |
| toronto.ca NPS page               | Nathan Phillips Square events | HTML scrape                   |
| Toronto Open Data (ArcGIS + CKAN) | Drop-in leisure skating       | Rink locations + schedules    |
| Ticketmaster Discovery            | Concerts, sports              | Needs`TICKETMASTER_API_KEY` |
| ~~Toronto Open Data festivals~~  | —                            | Disabled, see below           |

Run it locally with:

```sh
npm install
TICKETMASTER_API_KEY=... node fetch_events.js
```

Without the key, concerts and sports skip cleanly and the rest still runs.

## Failure handling

Every source can fail independently without taking down the build or silently
blanking a card. Three mechanisms:

- **A failed fetch returns `null`, never `[]`.** An empty array means "worked,
  nothing to report"; conflating the two is what previously let a transient 403
  silently delete a feature from the live site behind a green checkmark.
- **Per-source carry-forward.** GitHub Actions keeps a rolling cache of the last
  good `toronto_events.json`, and each source falls back to its previous data
  independently. This is safe because the client filters every list by date, so
  stale entries stop rendering on their own rather than showing wrong info.
- **Staleness is recorded, not hidden.** A `sources` block in the JSON carries a
  per-source `fetched` timestamp plus `stale` / `disabled` flags, and degraded
  sources surface as `::warning::` annotations in the workflow log.

The build stays green when a city API is down — a flaky third party should not
block deploying the site.

## Notable quirks

Things that look wrong but are deliberate, and things that bit us:

- **Festivals are disabled.** The Toronto Open Data festivals feed has been
  Akamai-blocked (403) since ~2026-06-14, and the CKAN-hosted "backup" resource
  serves a stale cached copy of that same error page. Every URL the dataset
  publishes leads to the same dead host. `FESTIVALS_ENABLED` in
  `fetch_events.js` flips it back if Toronto ever fixes it.
- **No ticket prices.** Ticketmaster's Discovery API returns no `priceRanges`
  for most events. The Inventory Status API does carry Canadian pricing
  but requires authorized access. Cards link out to Ticketmaster instead.
- **Ticketmaster is queried by `geoPoint` + a 60km radius, not `dmaId`.** The
  Toronto DMA both returned far-flung events (Thunder Bay, Windsor) and missed
  real Toronto ones. Tune the reach with `TORONTO_RADIUS_KM`.
- **`rankOptions()` is the single ordering rule.** A card's chosen item is
  element `[0]` and the **+** list is the rest.
  Each card supplies its own "available today" filter, because the predicate
  genuinely differs: a concert is out once it has started, a drop-in skate only
  once it has *ended*, and an NP Square event spans whole days.
- **Concerts use two-tier ranking.** Arenas and stadiums outrank everything
  else, each group internally by distance, so a stadium show wins over a closer
  club night. Sports is a flat pool — the three teams rank equally.

## Future directions

Ideas not yet built, roughly in order of appeal:

- **Live ticket prices** for concerts and sports, via a serverless Cloudflare
  Worker holding the key. Blocked for now on Ticketmaster access — see the
  no-prices note above.
- **Small live-music venues and bars** — the clubs Ticketmaster doesn't list
  (Horseshoe, Cameron House, Dakota, El Mocambo). No clean API exists, so this
  likely means per-venue scrapers.
- **Laptop-friendly cafes** — a card for the nearest spot to sit and work.
- **An inspiration section for activities** — a browse mode that just opens a
  Maps search for a category, no nearest-of calculation.
- **A better park database** — the current source has some false entries to
  weed out.
- **Library opening hours** — so the library card can say whether it's open now.

## Layout

```
index.html          markup, ⋮ menu, analytics + deep-link click handling
app.js              all client logic: geolocation, ranking, rendering
style.css           dark glass-card theme
sw.js               service worker, precache + stale-while-revalidate
manifest.json       PWA manifest (standalone, scoped to /HowFar/)
generate_data.py    manual: builds toronto_data.json
fetch_events.js     daily in CI: builds toronto_events.json
.github/workflows/deploy.yml
```

Runtime dependencies are CDN-loaded (Leaflet for the mini-map, Font Awesome,
Inter) — there is no build step or bundler. `npm install` exists only for
`fetch_events.js`.

Live APIs called from the browser: Open-Meteo (weather + air quality),
Bike Share Toronto GBFS, Nominatim (reverse geocoding), ipapi.co (fallback
location when GPS is denied), CARTO basemap tiles.

## Deploying

Push to `master`. The workflow fetches events, uploads the whole directory as a
Pages artifact and deploys. The daily cron does the same on a schedule.

For concerts and sports, set the API key once:

```sh
gh secret set TICKETMASTER_API_KEY
```

Note that GitHub disables scheduled workflows after 60 days of repository
inactivity, which stops the daily refresh silently.
